## 二、哪些工作可以加速

| 工作 | 加速方式 |
|---|---|
| 数据契约 | 集中定义schema并一次性补齐边界测试 |
| 决策内核 | 新实体旁路开发，完成后一次切换，不继续修旧流程 |
| 模拟执行 | 事件账本、费用、成交、T+1同时设计，共用黄金回放 |
| 调度可靠性 | 用户态worker、租约、回执和补偿一次实现 |
| 看板 | 先固定查询API，再并行拆页面组件 |
| 集成测试 | 用8月3—7日数据、合成行情和故障注入全天回放 |

不能加速：每天09:25/14:49/14:50/次日09:30的真实市场验证；足够交易笔数；
跨市场状态样本；Walk-Forward与压力测试所需时间跨度。

## 五、稳定性与策略样本

### 8月31日—9月25日：20交易日稳定性观察

只修工程缺陷，不按短期盈亏调整策略。目标SLA≥99%、重复成交0、未解释状态0、
账户对账差异0。该观察可以与日常使用并行，不阻塞看板和自动系统交付。

### 策略判断：不能用开发加速替代

初步判断仍至少需要40—60笔无人工选择的完整往返，并覆盖不同市场状态。所需日历
时间取决于BUY比例：

| 平均频率 | 40笔约需 | 60笔约需 |
|---|---:|---:|
| 每交易日1笔 | 2个月 | 3个月 |
| 每2个交易日1笔 | 4个月 | 6个月 |
| 每3个交易日1笔 | 6个月 | 9个月 |

模型生产准入仍由严格样本、Walk-Forward、压力测试、回撤和血缘门禁决定，不设日期。
