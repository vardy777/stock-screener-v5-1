## 二、工作流

工程流按P1→P5→集成验收顺序推进；严格数据采集作为独立证据流从第一天持续运行，
不得等待工程结束才开始积累。

```text
工程主线：P1数据 → P2决策 → P3执行 → P4调度 → P5看板 → 集成验收
证据支线：每日严格快照 → 配对标签 → 数据质量 → WF/压力测试（门槛满足后）
```

## 四、策略验证与模型时间

### 工程验证

2026-10-16前目标是证明系统“正确、稳定、可审计”，不是证明策略赚钱。

### 初步策略判断

至少需要40—60笔完整、无人工选择的V4往返交易，并覆盖不同市场状态。按实际
可交易频率估计约需2—5个月，预计窗口为2027年1—3月；若空仓比例高则更久。

### 生产模型准入

不设承诺日期。必须同时满足：

- 严格14:50/09:30样本最低量和足够交易日跨度；
- Walk-Forward窗口稳定；
- 双倍滑点/费用压力测试通过；
- 大亏概率、回撤、行业和市场状态分层可接受；
- 模型、特征、数据和报告哈希血缘一致；
- 发布清单可回滚。

在此之前始终保持 `research_locked`。

## 五、项目管理机制

### 每日

- 开始：运行 `scripts/project_status.py`；
- 结束：更新状态、测试、变更日志和当日证据；
- 不把聊天结论当作唯一记录。

### 每周五

- 演示本周可运行成果；
- 核对退出条件、风险和下周计划；
- 建立Git检查点；
- 未通过验收的阶段不得标记完成。

### 变更控制

以下变化必须先写ADR：评分口径、门禁、仓位、时点、费用、证据准入、数据供应商、
调度架构。生产门禁不得通过普通任务直接修改。

## 六、风险与缓冲

| 风险 | 影响 | 应对 |
|---|---|---|
| 行情接口不稳定/时间戳偏差 | 快照失败、误空仓 | 供应商适配、接收时间、母池二次刷新、原因码 |
| Windows任务权限不足 | 调度无法注册 | 独立用户态worker；管理员任务作为增强项 |
| 可交易日样本少 | 策略判断延迟 | 不降低门槛；持续采集严格全市场证据 |
| 评分重构改变候选 | 历史不可比 | 版本化策略、黄金回放、禁止静默覆盖 |
| 大改引入账户错误 | 收益失真 | 事件账本、逐分对账、只读迁移和回滚 |
| 需求扩张 | 关键闭环延期 | M6前冻结新增外围功能和视觉装饰 |

计划预留约20%缓冲。若P1/P2发现数据或评分定义需要研究决策，后续里程碑整体顺延，
不得跳过验收赶日期。
