# 项目路线图

阶段必须顺序推进。只有完成当前阶段退出条件，才能把下一阶段标记为进行中。

## P0 项目基线与契约冻结（已完成）

目标：建立唯一项目入口、机器可读状态、模块边界和自动检查。

退出条件：

- ChatGPT/Codex进入仓库能从 `AGENTS.md` 和 `PROJECT.md` 恢复上下文；
- 项目状态、架构、模块、运行手册、决策记录齐全；
- V4无V3导入检查、文档存在性检查和全量测试通过；
- 当前运行事实与已知问题记录准确。

## P1 数据、时间与交易日契约（当前）

目标：统一行情时间、交易日、覆盖率、新鲜度、盘口和快照口径。

退出条件：点时数据契约版本化；未来时间、批次延迟、停牌、涨跌停和缺失行情
均有测试；严格数据与paper-only降级路径在字段和目录上完全隔离。

## P2 候选与决策契约

目标：建立不可变的 `MorningPool`、`ConfirmationDecision` 和原因码。

P0问题：修复日志先保存旧门禁、母池重排分数口径变化、固定80分阈值不稳定。

退出条件：同一决策被推送、看板和执行共同读取；确认集合严格为母池子集；
空仓与阻断可区分；回放结果确定性一致。

## P3 模拟账户与执行引擎

目标：自动买卖、费用、滑点、仓位、T+1、幂等和失败重试形成独立模块。

退出条件：端到端回放覆盖买入、空仓、部分失败、次日卖出、节假日顺延；账户
永不重复成交；资金与逐笔记录可对账。

## P4 调度、推送与运行可靠性

目标：把业务调度从看板进程解耦，提供心跳、SLA、补偿和告警。

退出条件：看板停止不影响交易日任务；任务漏跑可补偿且不重复；09:25和14:50
推送有明确成功回执；故障能在看板和PushPlus告警。

## P5 看板与可观测性

目标：8898成为项目控制台，而不只是数据页面。

退出条件：展示状态机、数据时效、当日链路、账户、交易、胜率、回撤、原因码、
任务SLA和证据分层；所有数字有口径说明和来源时间。

## P6 研究数据集与评估

目标：持续积累无偏严格样本，完成Walk-Forward和压力测试。

退出条件：严格配对样本达到最低门槛；数据血缘可复现；窗口稳定性、费用敏感性、
行业和市场状态分层报告通过预先定义的验收标准。

## P7 模型训练、注册与发布

目标：训练可校准、可回滚、可审计的生产候选模型。

退出条件：训练只读严格数据；模型、特征、策略和报告哈希一致；发布清单原子化；
生产门禁全部通过后才允许将状态从 `research_locked` 改为准入。

## P8 运维与历史资产归档

目标：归档V2/V3和根目录旧实现，完善备份、恢复、升级与长期维护。

退出条件：运行路径只含V4；数据备份与灾难恢复演练通过；历史代码只读归档；
发布和回滚流程文档化。
