# P3隔离离线开发验收

更新：2026-08-08。P3只允许隔离离线开发；P1/P2真实窗口仍待验证。

## 强制边界

- 不注册或启用Windows任务；
- 不由看板、推送或现有定时入口调用；
- 不读写当前`v4/data`账户、持仓或成交文件；
- 不标记P3完成；
- P1/P2真实窗口失败时立即暂停P3并优先修复。

| 项目 | 实现 | 状态 |

| 成交实体 | `PaperFillV1`记录价格、费用、现金流和内容ID | 通过 |
| 往返实体 | `PaperRoundTripV1`严格配对买卖并计算净收益 | 通过 |

## 第二检查点（已通过）

- `OfflineIntentFactory`只接受最终BUY决策与版本化buy/sell快照；
- 未验证交易日历或缺少下一开放交易日时fail-closed；
- 周五买入冻结为下周一可卖，SELL再次执行T+1门禁；
- `OfflineExecutionEngine`逐项执行，一项失败不污染其他成功成交；
- 原子replace失败保留原账本，重载状态不变化；
- 对账报告校验现金、持仓、fill唯一性、SELL与往返记录数量；
- 完整离线买入—次交易日卖出回放通过并可重建。

## 第三检查点（已通过）

- 现金、费用和损益统一量化到分，账本同时输出可精确核对的`cash_fen`；价格保留独立精度；
- 订单、成交账本和执行结果日志在完整读—改—写期间持有OS级跨进程锁，避免并发丢失更新；
- `PaperExecutionResultV1`持久化FILLED/REJECTED结果及稳定原因码；
- 恢复扫描区分已成交、永久拒绝、存储故障待重试、孤儿成交，并可幂等重试待处理订单；
- 200次连续往返（400事件）现金、事件链和往返记录精确对账；
- 3标的交错持仓、乱序平仓、平仓后重开仓以及3进程并发写入通过；
- 覆盖磁盘写入失败、权限失败、订单已落盘但成交缺失、成交成功但结果日志失败和重启恢复；
- `LegacyAccountValidator`只读检查旧账户结构、资金、持仓和旧费用模型，不迁移、不双写、不切换生产。

## 仍待验证或未获授权

- P1/P2真实09:25、14:49、14:50及次交易日09:30窗口证据；
- P3生产调度、每日模拟成交链路接入、旧账户实际迁移和生产切换；
- 上述事项通过前P3阶段不得标记完成。

## 离线核心终审（已通过，但P3阶段未完成）

- 成交账本采用单文件原子提交和有序事件链，保存事件数与头部摘要；
- 删除、截断、重排或修改任一事件都会在重载时失败；
- 不可变订单日志补齐决策→订单→成交血缘，对账可验证所有fill均有order；
- SELL必须匹配原持仓decision、代码和股数，且成交时间晚于BUY；
- 同一股票平仓后可由新decision重新开仓并正确对账；
- 最多3只持仓和单只1/3资金上限均为账户硬门禁；
- ADR-0008规定未来只能原子单次切换，禁止旧账户与P3双写；
- 静态架构测试禁止现有生产入口导入任何P3模块。

以上全部完成也只能表示P3离线工程通过；在P1/P2真实窗口门禁解除前，P3仍不得连接生产链路或标记完成。
